# `principle-checklist` — 안내

사람이 읽는 문서다. 실행 중 적재되지 않는다 — 실행은 `SKILL.md`가 담당하고, `harvest` 모드에서는 `harvest.md`도 함께 적재된다.
English: `GUIDE.md` — 동일 내용; 한쪽을 고치면 다른 쪽도 고칠 것.

## 무엇인가

증거를 남기는 검사로 적용하는 엔지니어링 원칙들이다. 각 검사는 그것이 막으려는 실수를 아직 싸게
멈출 수 있는 단계에서 돈다: 계획할 때, 리뷰 finding 을 하나씩 고칠 때, 그리고 커밋이나 PR 전에.
변경 끝에 한 번 도는 체크리스트는 기억에 기대어 답해지고, 그래도 잡아낸 것은 재작업·재리뷰·시험
재실행을 부른다 — 검사를 단계별로 나누는 것이 잡는 시점을 앞당긴다.

## 호출

`/principle-checklist <모드> [principles-경로]` — `plan`, `fix`, `finish`, `harvest` 중 하나. 모드가
없으면 현재 상태에서 추론하고, 어느 모드를 골랐는지 밝힌다.

원칙 목록은 프로젝트의 `.claude/principles.md`(또는 지정한 경로)가 있으면 그것을, 없으면 동봉된
기본값 `principles.md` 를 쓴다.

## 설치

이 폴더를 `~/.claude/skills/` 에 복사하면 모든 세션에서, 프로젝트의 `.claude/skills/` 에 복사하면
그 프로젝트에서만 쓸 수 있다. 그 밖에 필요한 것은 없다 — 이 스킬에는 에이전트 프리셋도 명령도 없다.

**상태: 아직 실제 변경에 돌려 본 적 없음.** 단순한 슬라이스 하나로는 검증되지 않는다. 널리 공유하기
전에 실제 슬라이스에서 `plan`·`fix`·`finish` 를, 다른 저장소 하나에서 `harvest` 를 돌려 볼 것.

## 모드

| 모드 | 언제 | 산출물 |
|---|---|---|
| `plan` | 코드를 쓰기 전 | 계획이나 청사진에, 해당하는 원칙마다 한 줄 — 이 변경이 그것을 어떻게 막는지, 또는 이유를 단 `n/a`. 실제 외부 구성요소에 대한 탐침(probe)은 이때 돌린다(P6) |
| `fix` | 리뷰 finding 마다, 닫았다고 하기 전 | 결함 부류로 다시 쓴 finding, 저장소 전체의 형제 사례 검색(P2), 이전 검증 전부의 재실행(P1). finding 당 증거 한 줄 |
| `finish` | 커밋·푸시·PR 전 — 마지막 코드 변경 이후 | 변경된 줄에 대한 뮤테이션 패스(P4), 주장한 모든 수치와 강한 단어를 로그와 git 에서 다시 도출(P3), 계약 산출물이 같은 커밋에서 바뀌었는지 확인(P8) |
| `harvest` | 프로젝트가 자체 목록을 원할 때 | 프로젝트의 PR/MR 리뷰 이력에서 캐낸 `.claude/principles.md` (`harvest.md`) |

## 기본 원칙

`principles.md` 의 각 항목은 패턴, 예시, 검사, 그리고 기록할 증거 줄을 담는다.

| ID | 원칙 | 단계 |
|---|---|---|
| P1 | 수정이 원래 되던 것을 깨뜨린다 | fix, finish |
| P2 | 사례가 아니라 부류를 고친다 | fix |
| P3 | 주장은 최종 산출물과 일치해야 한다 | finish — 마지막 커밋·리베이스·머지 이후 |
| P4 | 새 코드를 지우면 시험이 실패해야 한다 | finish (plan 에서 의도한 시험을 명시) |
| P5 | 실패 경로는 드러나야 하고 상한이 있어야 한다 | plan, 첫 리뷰 |
| P6 | 외부 동작은 실제 시스템에서 확인한다 | plan |
| P7 | 파일시스템 신뢰 경계 | plan, 첫 리뷰 — 변경이 경로를 다룰 때만 |
| P8 | 동작이 바뀌면 계약도 함께 바뀐다 | plan, finish |

## 규칙

- **체크 표시가 아니라 증거.** 증거 줄 없이 원칙을 `applied` 로 표시하지 않는다. "시험이 통과한다"는
  P1 이나 P4 의 증거가 아니다.
- **`finish` 는 마지막 코드 변경 뒤에 돈다.** 그 뒤의 어떤 수정도 그것을 무효로 만든다.
- **첫 리뷰 패스는 원칙을 받고, 후속 패스는 받지 않는다.** 첫 패스는 해당하는 원칙을 명시적 항목으로,
  표면별로 나눠 받는다 — 코드: P1, P2, P4–P7; 문서와 계약: P3, P8. finding 이 닫혔는지만 확인하는
  패스는 아무것도 받지 않는다: 목록을 넘기면 라운드마다 범위가 넓어지고 루프가 수렴하지 않는다.
- **목록을 정직하게 유지한다.** 원칙은 그 표면을 건드린 최근 PR 에서 재발하지 않았을 때만 뺀다 —
  표면을 건드리지 않은 곳에서 안 보였다면 고쳐진 것이 아니라 모르는 것이다.

## 보고

```
Principles (<source>) — <mode>
P1 fix-induced regression    applied  | previous mutants 11/11 killed; replay 0 lost of 8,036 inputs
P4 deleting new code         deferred | 2 survivors (optional attr types) tracked in <where>, owner <who>
P7 filesystem trust          n/a      | change handles no paths
```

| 상태 | 뜻 |
|---|---|
| `applied` | 적용함, 증거 줄과 함께 |
| `n/a` | 해당 없음, 이유와 함께 |
| `deferred` | 여기서 하지 않음 — 어디에 기록했고 누가 맡는지 |
| `failed` | 커밋이나 PR 을 막는다 |

## 다른 저장소에 맞추기

기본값은 한 프로젝트의 패턴을 담고 있다; 다른 코드베이스는 다르게 실패한다. PR 몇 개를 거친 뒤, 또는
리뷰가 같은 종류의 문제를 계속 찾아낼 때 `harvest` 를 돌리고, 그 결과로 그 프로젝트의 기본값을
대체한다.

동봉 파일은 프로젝트 중립을 유지한다: 프로젝트 이름, 사람, 결정 ID, 내부 경로가 없다. 프로젝트 고유
내용은 — 예시에 든 PR 번호까지 — 프로젝트 자신의 `.claude/principles.md` 에만 둔다.
